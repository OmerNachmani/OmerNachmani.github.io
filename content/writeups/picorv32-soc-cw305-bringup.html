Overview

This writeup covers the RTL integration and hardware bring-up of a PicoRV32 RISC-V SoC on a ChipWhisperer CW305 Artix-7 board. The goal was a target that could run software AES-128, expose a deterministic first-round trigger, and accept chosen plaintexts through a host register bank — the measurement foundation for the power side-channel baseline.

The design was verified in simulation before the board was programmed. Four hardware checkpoints then confirmed identity, ciphertext correctness, cycle counts, trigger duration, and signal quality. The same build also exposed a logic-analyzer depth limit that shaped the capture configuration.

The identity contract is checked by the host before any mailbox write: ID = RSCV, VERSION = 2, core 2, workload 2, byte-count width 7, and a window byte (0 for the wide trigger, 1 for SubBytes). A stale bitstream cannot be mistaken for the intended build.

Simulation-first verification

Before synthesis, the SoC and the register path were exercised in simulation:

  • Four AES known-answer vectors matched OpenSSL, with result=0 and 181,090–181,096 cycles per encryption.
  • The narrow SubBytes trigger measured 1,865 cycles on all four vectors, matching the hardware window exactly.
  • The register-protocol testbench passed 78 checks and ran three consecutive AES operations through the bank.
  • A hand-assembled trigger smoke test returned 42 with a 34-cycle pulse.
  • All 35 saved GTKWave signal paths resolved in the regenerated waveforms.

The measured wide trigger duration equals the simulated 12,199 cycles, and the narrow window equals the simulated 1,865 cycles. The trigger bracket and the 10 MHz target clock are therefore confirmed on hardware, not only in simulation.

Logic-analyzer depth limit

The Husky logic analyzer stores 16,376 samples. A 10× oversampled record of the 12,199-cycle wide window would need 122,246 samples, and even the 1,865-cycle SubBytes window would need 18,650. The LA therefore runs at 1× the target clock, resolving each edge to about ±1 cycle. HS1 cannot be observed by an LA sampling at its own rate, so the helper records it as constant and relies on scope.clock.adc_locked for clock presence.

Two failed attempts are preserved as evidence of the limit: a 10× depth error and a hardcoded 100 MHz LA guard. The final configuration uses the ADC counter for the measured window width and the LA only for edge-level context.

Identity and operational safeguards

  • The RSCV identity check runs before any register write, so a stale bitstream cannot be used silently.
  • --reset-usb --program handles the known firmware 0.51 quirk of retaining an old bitstream.
  • MAX_CYCLES is 400,000; the AES workload needs 181,096, so a missing completion is detected rather than hanging.
  • The cycle acceptance band is ±100 around 181,092 because the xtime branches are data-dependent; a missing AES round differs by about 18,000 cycles.
  • Firmware stays at 0.51 deliberately: an interrupted 0.53 update would require SAM-BA or JTAG recovery, and the identity gate already covers the known quirk.

Limitations

  • One board, one target clock, one core voltage, and one toolchain; the timing and resource numbers are specific to this build.
  • The timing margin is 0.033 ns, so the result is sensitive to RTL, constraint, and tool-version changes.
  • The LA cannot oversample the windows, so sub-cycle timing is not resolved.
  • This writeup makes no side-channel or countermeasure claim; the attack results are documented separately.
